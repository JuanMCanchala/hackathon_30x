# Recibido Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Recibido, an accounts-payable agent that pays a services bill only for the work it
can prove was delivered, asks the contractor for what is missing, escalates the rest, plans when
and through which rail to pay, and reconciles every payment against a simulated bank statement.

**Architecture:** pnpm TypeScript monorepo, hexagonal like Mandato. `packages/domain` is pure
(no I/O): money, the decision engine (`decide`), receipts, the payment planner, the reconciliation
matcher, an independent invariant checker and metrics. `packages/dataset` holds the fictitious
company Altamar Labs Inc. (vendors, contracts, evidence fixtures, ~48 bill documents, the scripted
events of September and October 2026, expected outcomes, ground-truth readings) plus recorded LLM
responses. `apps/api` (Hono + zod-openapi, Drizzle on PGlite/Postgres) runs ingestion, LLM reading
and line matching with record/replay, evaluation, the vendor loop, evidence adapters (GitHub live
plus fixtures/CSV), the simulated Blinka rail and bank statement, the demo and the eval harness.
`apps/web` (Next.js 16 + Tailwind 4) has the Spanish landing, the app and the contractor portal.

**Tech Stack:** Node 24, pnpm 12.9.1, TypeScript ~6.0.3, Vitest 5, fast-check 4, zod 4, Hono 4 +
@hono/zod-openapi, Drizzle 0.45 + PGlite 0.5 / pg, unpdf, mailparser, pdf-lib (dataset only),
Next.js 16, React 19, Tailwind 4, SWR, Playwright (E2E and screenshots). Same versions as Mandato
(`git show feat/mandato:package.json`, `apps/*/package.json`, `pnpm-workspace.yaml`).

**Spec:** `docs/PROPOSAL.md` (approved design). Repo rules: `CLAUDE.md`. Reference implementation
for patterns (not concept or identity): Mandato in worktree `../30x-mandato` (branch `feat/mandato`).

## Global Constraints

- Code, docs, comments, commits in English. All user-facing UI text in Spanish (LatAm) with correct accents.
- The language model never decides a payment. It only (a) reads bill fields with confidence and (b) maps each bill line to a contract term with confidence. Hours, amounts, caps, dates, FX and outcomes are computed in code.
- Deny by default: a bill pays only if every check passes; a check that cannot run escalates.
- Money is integer minor units (`number`, safe-integer), never floats. Decimal strings parse with `parseDecimalToMinor` (copy from Mandato `packages/domain/src/money.ts`).
- Payments always go to the vendor's registered destination. Nothing in a bill or a vendor message can change it.
- Secrets only from environment; `env.example` lists names only. Keys available: `DEEPSEEK_API_KEY_PRINCIPAL`, `OPENROUTER_API_KEY`. Run keyed commands with `wallenv run -- <cmd>`. Never read `.env` files.
- Works with no API keys: recorded LLM responses replay; a cache miss without a key escalates as unreadable.
- Commits: Conventional Commits, small, no co-author or tool attribution lines. Never push mid-build (the controller pushes `feat/recibido` once at the very end). Never deploy. Never touch other branches/worktrees.
- Do not use claude-in-chrome or agent-browser. Visual checks with Playwright at 390 px and 1440 px.
- Company: **Altamar Labs Inc.** (US entity; contractors in Colombia, Mexico, Brazil). Do not reuse Mandato's names (Andes Labs, Valentina, Mateo, Camila, Tomás, Sebastián, Rafael, Lucía, Laura, Martín, Sofía).
- Package names: `@recibido/domain`, `@recibido/dataset`, `@recibido/api`, `@recibido/web`.
- Simulated clock: the demo and eval run on simulated time; nothing reads `Date.now()` for business logic (only for latency metrics).

## Review Focus

1. A bill that mentions a bank account equal to the registered one must NOT escalate; a different one, or any "cambio de cuenta" wording, must escalate (Task 3 tests both).
2. A corrected bill (revision) after a PAY_PART must never pay the already-paid part twice, and a revision is not a duplicate of the bill it supersedes (Task 3 + Task 8 tests).
3. Two different invoice numbers for the same contract and same period (hours/retainer/usage) or the same milestone twice must HOLD, not pay twice (Task 3 test `duplicate.work`).
4. A vendor reply that asks to change payout details escalates even when the attached corrected bill is otherwise perfect (Task 8 test).
5. A GitHub webhook with a bad signature, or a PR event for a PR no contract references, changes nothing (Task 9 test).

## Shared domain contract (all tasks rely on these names)

`packages/domain/src/types.ts` (Task 2 writes it exactly; later tasks import from `@recibido/domain`):

```ts
export type Currency = 'USD' | 'COP' | 'MXN' | 'BRL';
export type Country = 'CO' | 'MX' | 'BR' | 'US';
export type Rail = 'bre-b' | 'spei' | 'pix' | 'ach';
export type ContractType = 'hourly' | 'milestone' | 'retainer' | 'usage' | 'goods';
export type Outcome = 'PAY' | 'PAY_PART' | 'ASK_VENDOR' | 'ESCALATE' | 'HOLD';
export type BillStatus =
  | 'RECEIVED' | 'PAID' | 'PART_PAID' | 'AWAITING_VENDOR' | 'ESCALATED' | 'HELD'
  | 'APPROVED' | 'REJECTED' | 'SUPERSEDED';

export interface Vendor {
  id: string; name: string; legalName: string; country: Country; taxId: string; email: string;
  contactName: string;
  payout: { rail: Rail; currency: Currency; destination: string; display: string };
}

export type EvidenceRequirement =
  | { type: 'time_entries'; project: string }
  | { type: 'github_pr'; repo: string; number: number }
  | { type: 'deliverable'; deliverableId: string }
  | { type: 'ticket'; key: string }
  | { type: 'usage_report'; meter: string }
  | { type: 'delivery'; orderId: string };

export interface ContractTerm {
  id: string; kind: 'hours' | 'milestone' | 'retainer' | 'usage' | 'goods'; title: string;
  /** per hour (hours), per unit (usage/goods) or the fixed amount (milestone/retainer) */
  unitPriceMinor: number;
  /** null = the signed schedule is enough (retainer) */
  evidence: EvidenceRequirement | null;
}

export interface Contract {
  id: string; vendorId: string; type: ContractType; title: string; currency: Currency;
  validFrom: string; validTo: string | null;            // ISO dates
  terms: ContractTerm[];
  periodCapMinor: number;                               // per calendar month, contract currency
  netDays: number;
  earlyPayment: { discountBps: number; withinDays: number } | null;
  allowPartial: boolean;
  vendorResponseDays: number;
  evidenceRuleText: string;                             // Spanish, shown in the UI
}

export type EvidenceKind =
  | 'pr_merged' | 'pr_open' | 'time_entry' | 'ticket_closed' | 'ticket_open'
  | 'deliverable_accepted' | 'deliverable_pending' | 'usage_report' | 'delivery_confirmed';

export interface EvidenceItem {
  id: string; vendorId: string;
  source: 'github' | 'toggl' | 'linear' | 'entregables' | 'medidor' | 'entregas';
  origin: 'live' | 'fixture' | 'csv';
  kind: EvidenceKind;
  /** time_entry: project · PR: "owner/repo#n" · deliverable id · ticket key · meter · order id */
  ref: string;
  title: string; url: string | null; occurredAt: string;  // ISO datetime
  minutes?: number; quantity?: string; actor?: string;
}

export interface ExtractedLine {
  description: string; quantity: string | null;
  unit: 'hour' | 'unit' | 'milestone' | 'month' | 'other';
  unitPrice: string | null; amount: string | null;     // canonical decimals "1234.50"
}

export interface ExtractedBill {
  vendorName: string | null; vendorTaxId: string | null; invoiceNumber: string | null;
  issueDate: string | null; dueDate: string | null; periodFrom: string | null; periodTo: string | null;
  currency: string | null; total: string | null;
  lines: ExtractedLine[];
  payoutDetails: string | null;     // any bank account / key / payment instruction, verbatim
  revisionOf: string | null;        // invoice number this bill says it corrects
  instructionsToAgent: boolean;     // text addressed to an automated system
  confidence: { vendor: number; invoiceNumber: number; total: number; lines: number; currency: number; dates: number };
}

export interface LineMatch { lineIndex: number; termId: string | null; confidence: number; reason: string }

export interface Policy { minReadingConfidence: number; minMatchConfidence: number; autoPayLimitUsdMinor: number }
export const DEFAULT_POLICY: Policy = { minReadingConfidence: 0.85, minMatchConfidence: 0.8, autoPayLimitUsdMinor: 2_000_000 };

/** units of each currency per 1 USD, canonical decimals */
export interface FxSnapshot { asOf: string; perUsd: Record<Currency, string> }

export interface HistoryBill {
  billId: string; vendorId: string; contractId: string | null; invoiceNumberNormalized: string | null;
  status: BillStatus; paidMinor: number; currency: Currency | null;
  periodFrom: string | null; periodTo: string | null; termIds: string[];
  /** ids of the bill and every bill it supersedes, transitively */
  chain: string[];
}

export interface DecisionContext {
  now: string; policy: Policy; fx: FxSnapshot;
  bill: {
    id: string; reading: ExtractedBill | null; readingError: string | null;
    /** text we could read ourselves (PDF text layer, e-mail body, chat, vendor message) */
    documentText: string | null;
    receivedAt: string; channel: 'pdf' | 'email' | 'chat' | 'portal';
    chain: string[];  // this bill + bills it supersedes
  };
  vendors: Vendor[]; contracts: Contract[];
  matches: LineMatch[] | null; matchError: string | null;
  evidence: EvidenceItem[];         // every evidence item of the resolved vendor
  history: HistoryBill[];           // every other bill of the organization
  case: { paidMinor: number; askedAt: string | null };
}

export type CheckId =
  | 'reading.available' | 'reading.confidence' | 'reading.instructions' | 'reading.arithmetic'
  | 'reading.period' | 'vendor.registered' | 'vendor.payout' | 'contract.active'
  | 'contract.currency' | 'duplicate.invoice' | 'duplicate.work' | 'match.confidence'
  | 'terms.lines' | 'terms.price' | 'terms.cap' | 'policy.limit' | 'evidence.coverage'
  | 'vendor.deadline';

export interface CheckResult {
  id: CheckId; stage: 'lectura' | 'proveedor' | 'duplicado' | 'contrato' | 'evidencia' | 'plazo';
  status: 'pass' | 'fail' | 'not_run'; onFail: Outcome;
  label: string; detail: string; remedy: string | null;   // Spanish
}

export interface LineEvaluation {
  lineIndex: number; description: string; termId: string | null; termTitle: string | null;
  billedMinor: number; evidencedMinor: number;
  billedQuantity: string | null; evidencedQuantity: string | null;
  status: 'evidenced' | 'partial' | 'missing' | 'not_required' | 'unmatched';
  evidence: EvidenceItem[];       // items that count
  supporting: EvidenceItem[];     // shown but not counted (e.g. merged PRs behind hours)
}

export interface Decision {
  outcome: Outcome; vendorId: string | null; contractId: string | null; currency: Currency | null;
  billedMinor: number; evidencedMinor: number; alreadyPaidMinor: number; payNowMinor: number; askMinor: number;
  checks: CheckResult[]; lines: LineEvaluation[];
  summary: string; counterfactual: string[]; vendorMessage: string | null;
  engineVersion: string;
}
```

Checks, in this order, with `onFail` and stage (all text Spanish; `detail` cites the observed vs expected values; `remedy` says what would make it pass):

| id | stage | onFail | passes when |
| --- | --- | --- | --- |
| reading.available | lectura | ESCALATE | `reading !== null` |
| reading.confidence | lectura | ESCALATE | every confidence ≥ `policy.minReadingConfidence` |
| reading.instructions | lectura | ESCALATE | `!reading.instructionsToAgent && !scanInstructions(documentText)` |
| reading.arithmetic | lectura | ASK_VENDOR | every line amount = qty × unit price (±1 minor) when both present, and Σ lines = total |
| reading.period | lectura | ASK_VENDOR | contract type hourly/retainer/usage ⇒ periodFrom and periodTo present |
| vendor.registered | proveedor | ESCALATE | `resolveVendor` finds a vendor |
| vendor.payout | proveedor | ESCALATE | no `mentionsPayoutChange` in reading.payoutDetails/documentText, and every `scanPayoutMentions` candidate (from payoutDetails and documentText) equals the registered `normalizeDestination(destination)` |
| contract.active | contrato | ESCALATE | active contract for the issue date |
| contract.currency | contrato | ESCALATE | bill currency = contract currency |
| duplicate.invoice | duplicado | HOLD | no history bill outside `bill.chain` of the same vendor with the same normalized invoice number and status not in {REJECTED, SUPERSEDED} |
| duplicate.work | duplicado | HOLD | hourly/retainer/usage: no history bill outside chain, same contract, overlapping period, status in {PAID, PART_PAID, AWAITING_VENDOR, APPROVED, ESCALATED}; milestone/goods: no such bill containing any of this bill's matched termIds |
| match.confidence | evidencia | ESCALATE | matches present (`matchError===null`) and each confidence ≥ `policy.minMatchConfidence` |
| terms.lines | contrato | ASK_VENDOR | every line maps to a term (`termId !== null` and exists in contract) |
| terms.price | contrato | ASK_VENDOR | each line unit price (hours/usage/goods) or amount (milestone/retainer) ≤ term.unitPriceMinor |
| terms.cap | contrato | ESCALATE | Σ paidMinor of other history bills of the contract in the same month (by periodFrom, else issueDate) + max(evidencedMinor, case.paidMinor) ≤ periodCapMinor |
| policy.limit | contrato | ESCALATE | `convertToUsdMinor(payNowMinor)` ≤ `policy.autoPayLimitUsdMinor` |
| evidence.coverage | evidencia | `PAY_PART` if `contract.allowPartial && evidencedMinor>0`, else ASK_VENDOR | evidencedMinor = billedMinor |
| vendor.deadline | plazo | ESCALATE | `case.askedAt === null` or `daysBetween(askedAt, now) <= contract.vendorResponseDays` or coverage passes |

Aggregation (deny-by-default): any `not_run` counts as ESCALATE; outcome = most severe of failing `onFail` by `HOLD > ESCALATE > ASK_VENDOR > PAY_PART > PAY`; all pass → PAY. When a stage's inputs are missing, its checks and every later check are `not_run` with detail "No se pudo verificar: …". Amounts: `billedMinor` = parsed total; `alreadyPaidMinor = case.paidMinor`; PAY → `payNowMinor = max(0, billedMinor − alreadyPaid)`; PAY_PART → `payNowMinor = max(0, evidencedMinor − alreadyPaid)` and, if that is 0, outcome becomes ASK_VENDOR; every other outcome → `payNowMinor = 0`; `askMinor = billedMinor − evidencedMinor` for PAY_PART/ASK_VENDOR else 0. A PAY whose `payNowMinor===0` means "lo evidenciado ya estaba pagado" and closes the case.

`explain.ts`: `summarize(decision, ctx): string` (one Spanish sentence per outcome, citing numbers, e.g. PAY_PART: "Pagamos 92 h de 160 h facturadas: hay registro de 92 h en Toggl para octubre. Pedimos a Daniela el soporte de las 68 h restantes."), `counterfactual(checks): string[]` (remedies of failing checks), `vendorMessage(decision, ctx): string | null` for ASK_VENDOR and PAY_PART, addressed to `vendor.contactName` first name, e.g. "Hola Daniela: facturaste 160 h en la cuenta DO-2026-10 y hay registro de 92 h para octubre. Ya programamos el pago de las 92 h. ¿Puedes adjuntar el registro del resto o enviar la cuenta corregida?". Never includes payout details. Generated from code, not by the LLM.
